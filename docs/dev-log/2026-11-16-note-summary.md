# 2026-11-16 AI 노트 요약

## 정한 것 (사용자)
- 노트 기능 추가 후보 중 **AI 노트 요약**과 **노트 공유 커뮤니티**를 고름 → 요약 먼저, 커뮤니티는 설계부터
- 요약 내용: **핵심 요약 3~5줄 + 제목 추천** (키워드·복습 질문은 뺌)
- 보여 줄 곳: **노트 안 + 목록 카드**

## 만든 것
- 노트 위쪽 [AI 요약] → 오른쪽 요약 칸(폰은 아래)
  - 필기가 있는 페이지(최대 10장)를 900px 흰 바탕 PNG로 그려 보냄. 보정된 글자는 보정 글씨체로
  - Gemini가 **손글씨를 직접 읽고** 요약 → 보정 안 한 필기도 요약되고, 글자 인식(Vision) 하루 30번을 쓰지 않음
  - 요약 줄, 제목 추천 [제목으로 쓰기](누를 때만 바뀜), 요약 시각, [다시 요약]
  - 요약 뒤에 필기가 바뀌면 "요약한 뒤에 노트가 바뀌었어요"
- 목록·홈 카드 제목 아래 요약 첫 줄
- 서버 `POST /api/notes/{id}/summary`
  - Gemini에 `responseMimeType: application/json` + `responseSchema`({ summary: [줄], title })로 정해진 형식만 받음. 줄 앞 번호·기호 제거, 최대 5줄, 한 줄 150자 넘으면 실패, 제목은 40자 넘으면 버림
  - 요약은 `note.summary`(줄바꿈으로 이어 붙임) + `summarized_at`에 저장 (Flyway **V4**). 제목 추천은 저장 안 함
  - 요약 저장은 JPQL update로 → `@PreUpdate`가 `updated_at`을 바꾸지 않아 "요약 뒤에 바뀜" 판단이 맞음
  - 키는 연습 조언과 같은 `ddobak.advice.gemini.api-key`, 계정마다 하루 20번(`ddobak.summary.daily-limit`), 실패는 횟수에서 빼고 503 "지금은 요약을 만들 수 없어요"
  - PNG data URL 검사를 `common/PngDataUrl`로 빼서 연습 조언과 같이 씀

## 확인
- 백엔드 110개(요약 저장·수정 시각 그대로·실패·한도·남의 노트·Gemini 요청 형식), 프론트 220개
- Playwright iPad·폰: 빈 노트 안내 → 필기 → 요약 → 제목 적용 → 필기 추가 시 "바뀜" → 실패 안내 → 홈 카드 요약 → 다시 열면 저장된 요약
- 실제 Gemini 호출은 키를 넣고 사용자가 확인해야 함 (손글씨 읽기 품질)
