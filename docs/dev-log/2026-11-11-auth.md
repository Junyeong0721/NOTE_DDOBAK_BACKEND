# 2026-11-11 메인 화면 · 회원가입 · 로그인 (1단계: 이메일)

## 만든 기능
- 로그인 전 소개 화면: 흘려 쓴 "오늘 배운 내용 정리"가 반듯한 글씨체로 맞춰지는 시연 한 번, 기능 세 줄(바인더 인덱스 색 띠)
- 로그인 / 회원가입: 이메일·비밀번호·닉네임, 입력 칸 바로 아래 오류 안내(서버와 같은 규칙·문구), 비밀번호 보기
- 로그인 후 홈: 인사, 새 노트, 이어 쓰기(최근 4개), 모든 노트, 글씨 연습(곧 열려요), 로그아웃
- 노트·폴더를 계정별로 나눔. 남의 노트는 없는 것처럼 404. 글자 인식도 로그인해야 쓸 수 있음(하루 한도 보호)
- Google·카카오 버튼 자리만 만들어 둠(2단계)

## AI에게 준 요청
- "메인화면이랑 로그인 회원가입도 만들고 싶은데"
- 결정: 화면은 소개+홈 둘 다, 이메일 가입 + 소셜 로그인(다른 앱들처럼), 기존 노트는 지우고 새로 시작, 가입 정보는 이메일·비밀번호·닉네임

## 받은 결과 요약
- **소셜 로그인은 2단계로**: Google·카카오는 "로그인 후 돌아올 주소"를 미리 등록해야 하는데, 지금 터널 주소는 켤 때마다 바뀜 → 고정 주소(Tailscale) 먼저
- **라이브러리 추가 없이**: Spring Security가 PC의 Gradle 캐시에 없어 AI 환경에서 테스트할 수 없음 → 자바 기본 기능으로
  - 비밀번호: PBKDF2-HMAC-SHA256 60만 번(OWASP 권장), 회원마다 다른 소금, 형식 `pbkdf2$횟수$소금$해시`(횟수를 같이 저장해 나중에 올려도 옛 해시 확인 가능), 비교는 걸린 시간이 같게(`MessageDigest.isEqual`)
  - 로그인 유지: 서버 세션에 회원 번호만. 로그인할 때 세션 번호 바꿈(세션 고정 공격 방지), 쿠키 HttpOnly·SameSite=Lax·30일, 서버를 다시 켜도 세션 유지(`persistent`)
  - 로그인 검사: `/api/auth` 를 뺀 모든 `/api` 요청을 인터셉터에서 확인, `@LoginUser Long userId`로 컨트롤러에 전달
- 이메일이 없을 때와 비밀번호가 틀릴 때 같은 문구 → 가입 여부를 알아낼 수 없음
- 기존 노트: DB의 주인 칸을 null 허용으로 두어 예전 데이터가 있어도 서버가 켜지고, 주인 없는 예전 노트는 아무에게도 안 보임 + PC의 H2 파일 삭제

## 오류와 해결
| 오류 | 원인 | 해결 |
| --- | --- | --- |
| 첫 화면이 하얗게 나옴 | 시연 문장(11글자)보다 글자별 흔들림 값(10개)이 적어 범위를 벗어남 | 값 추가 + 나머지 연산으로 안전하게 |
| 시연 종이의 줄이 글자를 가로지름 | 줄 간격과 글자 줄 높이가 안 맞음 | 줄을 하나만, 글자 바로 아래에 |
| 테스트용 로그인 MockMvc에서 한글 오류 문구가 깨질 위험 | 직접 만든 MockMvc에는 인코딩 필터가 없음 | `CharacterEncodingFilter(UTF-8)` 추가 |
| 테이블 이름 `user` | H2·MySQL 예약어 | `users` |

## 내가 이해한 핵심 3줄
1. 비밀번호는 저장하지 않는다 — 복원할 수 없는 해시만, 느리게(반복) 만들고 사람마다 소금을 다르게.
2. 로그인 확인은 화면이 아니라 서버가 매 요청마다 한다. 화면은 401을 받으면 로그인으로 돌아가기만 한다.
3. 외부 서비스(소셜 로그인)는 내 쪽 준비(고정 주소)가 먼저다.

## 검증
- 백엔드 테스트 67개 통과(가입·로그인·로그아웃·검증 문구·대소문자 무시 중복·계정 간 분리·로그인 없이 401, 비밀번호 해시 3개 추가)
- 실제 서버를 켜서 가입(0.6초)·로그인·쿠키(30일, HttpOnly, SameSite=Lax) 확인
- 프론트 테스트 162개, Playwright: 소개 → 가입(오류 안내) → 홈 → 새 노트 → 홈 → 모든 노트 → 홈 → 로그아웃 → 틀린 비밀번호 → 로그인 → 새로고침해도 로그인 유지, iPad·휴대폰 크기 화면
