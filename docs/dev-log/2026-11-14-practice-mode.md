# 2026-11-14 글씨 연습 모드

설계: `docs/superpowers/specs/2026-11-13-practice-mode-design.md`, 계획: `docs/superpowers/plans/2026-11-14-practice-mode.md`

## 만든 것

- **고르기 → 쓰기 → 결과** 세 화면 (홈의 "글씨 연습" 카드)
  - 연습할 글씨체를 연습 화면에서 고른다(5종). 노트 보정 글씨체와 따로 기억한다.
  - 미리 넣은 세트 16개(자음·모음 / 글자 / 단어 / 문장) + 직접 입력(한글 30자까지)
  - 원고지 칸에 연한 목표 글자(가이드)를 따라 쓴다. 가이드는 끌 수 있다.
  - [한 획 되돌리기] [칸 지우기] [전체 다시] [채점하기]
- **점수는 앱이 계산** (`src/practice/score.js`, 브라우저 없이 도는 순수 함수)
  - 목표 글자와 내 글씨를 64×64 모눈으로 바꿔 비교: 모양 50 + 위치·크기 25 + 기울기 25
  - 같은 획이면 항상 같은 점수. 채점은 0.2초 안쪽.
- **조언은 AI(Gemini 무료 등급)** — 목표 글씨와 내 글씨를 위아래로 맞춘 그림 + 글자별 점수를 보내 한두 문장을 받는다.
  - 기록을 먼저 저장하고 조언을 붙인다. 조언이 안 되면 "지금은 조언을 할 수 없어요"만 보이고 점수·기록은 그대로.
  - 회원마다 하루 50번, 실패한 호출은 횟수에서 빼지 않는다. 키가 없으면 가짜 조언.
- **기록**: `practice_attempt` 표(V2, Flyway). 고르기 화면에 세트별 최고 점수·횟수, 최근 연습 20개(누르면 다시 보기).

## 설계에서 달라진 점

- **채점 식을 다듬었다.** 처음 식(겹치는 비율만)으로는 테스트에서 문제가 드러났다.
  - ㅏ에서 짧은 가로 획을 빼도 ㅣ와 95% 겹쳐 만점에 가까웠다 → "가장 동떨어진 잉크의 거리"를 같이 봐서 획을 빼먹거나 엉뚱한 획을 그으면 모양 점수가 깎이게 했다.
  - 점 하나만 찍어도 글자 크기로 부풀려져 점수가 났다 → 크기 맞춤을 3배까지로 제한.
  - 획 하나가 빠지면 글자 상자 가운데가 밀려 엉뚱하게 맞춰졌다 → 상자 가운데 대신 잉크의 무게 중심으로 맞춤.
  - 낙서가 자리만 맞아도 위치·기울기 50점을 받았다 → 모양이 절반에 못 미치면 위치·기울기도 같이 줄인다.
  - "근처면 1점, 아니면 0점" 대신 거리에 비례해 점수를 준다(획이 빽빽한 글자에서 낙서가 다 "근처"로 잡히던 문제).
  - 기준값은 `SCORE_TUNING` 한곳에 있다. **실제 손글씨로 써 보고 조정해야 한다.**
- **한글이 아닌 글자**(영문·숫자·기호)는 칸만 보여 주고 쓰지도 채점하지도 않는다. (글꼴에 없는 글자는 브라우저가 다른 글꼴로 그려 버려서 "글꼴에 없음"을 잉크로 판별할 수 없었다)
- **칸 지우기**는 "칸을 눌러 선택" 대신 [칸 지우기]를 누르고 지울 칸을 누르는 방식(칸을 누르면 점이 찍히므로). [한 획 되돌리기]를 추가.
- 폰처럼 좁은 화면에서는 한 줄 칸 수를 줄여 칸이 64px보다 작아지지 않게 한다(획은 칸 기준 좌표라 배치와 무관).
- DB: `guide`는 `BIT(1)`(Hibernate가 MySQL에서 boolean에 쓰는 타입과 같게), `char_scores`도 `LONGTEXT`, 연습한 글 칸 이름은 `target_text`.
- "잘못된 노트 번호입니다." → "잘못된 번호입니다." (연습 기록 주소에도 쓰이게 됨)

## 확인한 것

- 프론트 테스트 203개, 백엔드 94개 통과. MySQL용으로 Hibernate가 만드는 표 정의와 V2 SQL의 타입이 같은지 비교.
- Playwright로 iPad·폰 크기에서 전체 흐름: 목표 글자를 그대로 따라 쓰면 98점, 옆으로 밀면 위치만, 기울이면 기울기만 깎임, 낙서는 30점대, 연타해도 저장 1번, 저장 실패·조언 실패 안내, 다시 보기, 글씨체 바꾸기, 직접 입력, 30자 3줄.

## 같은 날 저녁: 랜덤 5문제로 변경 (사용자 요청)

- 단계는 **글자·단어·문장** 세 개만. 자음·모음 단계, 미리 넣은 세트, 직접 입력은 없앰
- 단계를 고르면 문제 **5개가 랜덤**으로 나온다 (글자 160여 개, 단어 100여 개, 문장 50개 목록에서, 한 판 안에서 겹치지 않고 바로 전 판과도 겹치지 않게)
- 쓰기 화면은 한 문제씩 "2 / 5", [이전 문제]·[다음 문제], 번호 동그라미로 바로 이동. 5번째에서 [채점하기]. 안 쓴 문제는 0점이라고 미리 알려 준다
- 결과: 판 점수 = 문제 점수 5개의 평균, 문제마다 겹쳐 보기와 글자별 점수. 조언은 판마다 한 번(문제 5개를 그림 한 장에)
- 저장: 한 판 = 기록 하나. 이미 V2가 적용된 DB가 있을 수 있어 V2는 그대로 두고 **V3**에서 `stage` 추가, `set_id` 삭제, `target_text`를 300자로(문제를 줄바꿈으로 이어 저장). 모양이 다른 V2 시절 시험 기록은 V3에서 지운다
- 고르기 화면의 최고 점수는 단계별로
