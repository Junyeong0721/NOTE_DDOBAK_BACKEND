# 2026-10-31 2주차: 필기 캔버스, 줄 묶기, 노트 정리, PWA

## 만든 기능
- 필기 캔버스: Apple Pencil 필압, 펜·마우스만 그리기(손바닥 무시), 손가락 스크롤, 지우개(획 단위), 실행 취소/다시 실행(50단계), 1초 뒤 자동 저장
- 필기 데이터 형식: A4 비율 페이지 좌표(가로 1000), 점 `[x, y, 필압, ms]`, 원본은 그대로 두고 정리·보정은 획별 `transform`으로 저장
- 줄 묶기와 글씨/그림 판정 (`src/note/lines.js`)
- 노트 정리: 글씨 줄만 기울기 펴기, 왼쪽 맞춤, 문단 안 줄 간격 맞춤. 그림은 그대로 (`src/note/tidy.js`)
- 한 줄이 끝나면 줄 이미지를 PNG로 만들어 OCR API 호출 (2주차는 가짜 응답, 3주차에 Google Cloud Vision)
- 백엔드: 필기 데이터 형식 검사 강화, `POST /api/ocr/line` (PNG 검사, 2MB 제한, `OcrClient` 인터페이스)
- PWA: 홈 화면 아이콘 "또박", 주소창 없는 전체 화면

## AI에게 준 요청
- 무지 페이지에서 글씨와 그림을 구분하는 방법 설계
- 필기 데이터 형식 설계, 2주차 구현 계획 작성과 실행

## 받은 결과 요약
- 핵심 난제는 "줄이 있냐 없냐"가 아니라 "글씨와 그림을 구분하는 것" → 무지 페이지로 결정
- 판정 규칙: 세로로 30% 이상 겹치거나 받침처럼 살짝 아래면 같은 줄, 보통 글자 높이의 2.5배보다 크거나 가늘고 긴 획(밑줄·화살표)은 그림
- 노트 정리는 매번 원본 기준으로 다시 계산 → 두 번 해도 결과가 같고, "정리 취소"는 transform만 지우면 됨

## 오류와 해결
| 오류 | 원인 | 해결 |
| --- | --- | --- |
| 계획의 줄 묶기 규칙으로는 받침이 다음 줄로 떨어짐 | 받침은 같은 글자의 윗부분과 세로로 겹치지 않음 | "살짝 아래(글자 높이의 35% 이내)"도 같은 줄로 허용, 큰 획은 글씨 줄에 합치지 않음 |
| Vite 템플릿 CSS 때문에 에디터 화면이 가운데 좁게 나옴 | 템플릿이 `#root` 폭 1126px 고정, 가운데 정렬, 다크 모드 | 앱 전용 기본 CSS로 교체 |
| 에디터 커밋이 다음 커밋의 파일을 불러와 중간 커밋이 빌드 안 됨 | 커밋 순서 | 순서를 바꿔 다시 커밋, 모든 커밋 빌드 확인 |
| AI 작업 환경에서 Maven·npm 접속 불가 | 네트워크 제한 | 순수 함수 테스트는 작은 Vitest 호환 실행기로, 화면은 빌드 후 Chromium으로 확인. 최종 확인은 PC에서 |

## 검증
- 백엔드 테스트 26개, 프론트 테스트 58개 통과 (PC)
- 브라우저 자동 확인: 새 노트 → 쓰기 → 자동 저장 → 줄 끝 OCR → 노트 정리 → 실행 취소 → 지우개 → 제목 수정 → 다시 열기, 콘솔 오류 0
- iPad 직접 확인: 필압, 손바닥 무시, 스크롤, 줄 보기, 노트 정리, 홈 화면 추가

## 내가 이해한 핵심 3줄
1. 원본은 절대 바꾸지 않고 변환(transform)만 따로 저장하면, "정리"와 "정리 취소", 나중의 글자 보정까지 모두 되돌릴 수 있고 두 번 실행해도 결과가 같다.
2. 화면 픽셀이 아니라 페이지 좌표(가로 1000)로 저장해야 iPad를 돌리거나 PC에서 열어도 글씨 위치가 같다.
3. 글씨/그림 판정은 정답이 있는 문제가 아니라 기준값을 정하는 문제다. 값을 상수로 모아 두고 테스트로 동작을 고정한 뒤, 실제 필기로 조정한다.
