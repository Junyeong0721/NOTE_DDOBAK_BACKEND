# 2026-11-09 글자 인식을 Google Cloud Vision으로 연결

## 만든 기능
- `GoogleVisionOcrClient`: 줄 이미지를 Vision `DOCUMENT_TEXT_DETECTION`(손글씨 포함, 언어 힌트 `ko`)으로 보내고, 글자(symbol)마다 위치 상자·신뢰도를 `OcrChar`로 바꿔 돌려줌
- `OcrConfig`: API 키가 있으면 Vision, 없으면 가짜 응답. 서버 시작 로그에 어느 쪽인지 표시
- 키 보관: 백엔드 폴더의 `secret.yaml`(`.gitignore` 등록, `spring.config.import: optional:file:./secret.yaml`). 틀은 `secret.example.yaml`. 환경 변수 `GOOGLE_VISION_API_KEY`도 계속 지원
- `OcrUsageLimiter`: 하루(한국 시간) 30번까지만 인식 → 넘으면 429 "오늘 글자 인식 횟수(30번)를 다 썼습니다." (`OCR_DAILY_LIMIT`로 조정)
- 오류를 사용자가 이해할 수 있는 말로: 키·결제 문제(400/401/403) → "설정을 확인해 주세요", Google 한도(429) → 429, 그 밖 → 502 "연결하지 못했습니다"

## AI에게 준 요청
- "가짜 응답 말고 진짜 응답으로 만들자"

## 받은 결과 요약
- 후보 비교: Google Cloud Vision(월 1,000번 무료, 글자별 위치 제공, 카드 등록 필요) vs Gemini API(카드 없이 무료, 글자별 위치가 부정확, 무료 등급은 입력이 제품 개선에 쓰일 수 있음)
- 보정 기능은 "글자별 원래대로"와 보정 글자 배치에 **글자별 위치**가 꼭 필요 → Vision 선택
- Vision에는 '하루 N번' 같은 확실한 상한이 Google 쪽에 없음 → **서버에서 하루 횟수를 센다**. 서버가 Cloudflare 터널로 외부에 열려 있어서, 누가 반복 호출해도 요금이 안 나가게 하는 목적도 있음 (30번 × 30일 = 900번 < 무료 1,000번)
- API 키는 저장소에 넣지 않음. 처음엔 환경 변수(`setx`)를 제안했는데, 키가 눈에 보이고 바로 고칠 수 있는 `.gitignore` 파일 방식으로 결정 (속도 차이 없음, 둘 다 PC마다 한 번 설정). 대신 `secret.example.yaml`만 올리고 진짜 `secret.yaml`은 무시 목록에 넣음
- 요청은 URL 쿼리(`?key=`)가 아니라 `X-Goog-Api-Key` 헤더로 보내서 오류 로그에 키가 남지 않게 함

## 오류와 해결
| 오류 | 원인 | 해결 |
| --- | --- | --- |
| AI 작업 환경에서 백엔드 테스트를 돌릴 수 없음 | Maven 접속 차단 | PC의 Gradle 캐시(`~/.gradle`)에 이미 받아 둔 jar를 복사해 javac + JUnit 실행기로 직접 컴파일·테스트. 이제 PC에 넘기기 전에 백엔드도 확인 가능 |
| Vision 응답에서 좌표가 0인 꼭짓점은 `x`/`y`가 아예 빠짐 | protobuf JSON은 기본값(0)을 생략 | 빠진 좌표는 0으로 읽고, 그 경우를 테스트로 고정 |

## 내가 이해한 핵심 3줄
1. 외부 API는 "인터페이스 + 가짜 구현"으로 먼저 흐름을 만들고, 키가 생기면 구현만 갈아끼운다 (`OcrClient`).
2. 유료가 될 수 있는 API는 비용 상한을 내 서버에서 직접 건다 — 외부 서비스 설정만 믿지 않는다.
3. 비밀 값(API 키)은 저장소·로그 어디에도 남지 않게: `.gitignore`된 `secret.yaml`(또는 환경 변수) + 헤더 전송.

## 검증
- 서버를 실제로 켜서 확인: `secret.yaml`이 있으면 "글자 인식: Google Cloud Vision", 없으면 "가짜 응답" 로그
- 백엔드 테스트 57개 통과 (AI 작업 환경, PC Gradle 캐시의 같은 라이브러리로): Vision 요청 형식·응답 해석·오류 4종, 하루 한도·자정 초기화, 한도 초과 시 API 429, 키 유무에 따른 구현 선택
